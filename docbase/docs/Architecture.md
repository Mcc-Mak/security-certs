## Deployment surfaces

### GitHub Pages (Docsify)

- **No build step** — Docsify renders markdown client-side via JavaScript
- `pages/index.html` loads Bootstrap 5.3 (CDN + SRI), then Docsify theme (CDN + SRI), then docsify-sidebar-collapse plugin — Bootstrap first so Docsify overrides conflicts
- Bootstrap Icons are self-hosted under `pages/vendor/bootstrap-icons/` (no CDN dependency for icons)
- `pages/README.md` is the TOCTREE landing page — Bootstrap card grid with exam identity colors (`primary` for Network+, `success` for CISSP) and category badges (`primary`=sessions, `info`=diagrams, `warning`=question bank, `secondary`=reference PDFs)
- `pages/_sidebar.md` provides persistent Docsify navigation (auto-generated by `build-pages.sh` with all session links; uses absolute `/`-prefixed paths for `relativePath: true` compatibility)
- Sidebar is collapsible (docsify-sidebar-collapse plugin) with `sidebarDisplayLevel: 1` — Overview expanded, exam folders collapsed by default
- Sidebar also includes Diagrams and Reference PDFs links (`?id=diagrams`, `?id=reference-pdfs`) auto-generated by `build-pages.sh`
- `codebase/{exam}/README.md` provides per-exam session tables with clickable links to each session file, plus Diagrams and Reference PDFs sections
- `codebase/isc-cissp/question-bank/README.md` is the question-bank index — Bootstrap cards with `primary` for domain-specific tests and `danger` for full practice tests
- Raw HTML `<a>` tags in exam READMEs use site-root-relative paths (e.g. `isc-cissp/note/chapter/intermediate/session-30.md`) for `relativePath: true` compatibility
- `scripts/build-pages.sh` assembles `_site/` by copying `pages/` shell + `pages/vendor/` + `codebase/` content, and auto-generates `_sidebar.md` with all chapter session links, question-bank links, and diagrams/reference anchors
- `.nojekyll` disables Jekyll processing so raw `.md` files are served
- `relativePath: true` in the Docsify config ensures content-relative links work under the Pages subpath
- Search plugin uses `paths: 'all'` to index all sidebar-linked pages (all 62 sessions)
- `searchFilenamePlugin` (custom Docsify plugin) uses a MutationObserver to replace search result titles with filenames instead of page titles
- CSS overrides: `.sidebar-nav li.collapse { display: list-item !important; }` prevents Bootstrap `.collapse` from hiding sidebar folder labels; `.card .badge, .card .btn { align-self: flex-start; }` prevents button/badge stretching in flex-column card bodies

### GitHub Wiki

- `scripts/sync-wiki.sh` publishes `docbase/` engineering docs only (no study notes)
- `Home.md` is generated from the root `README.md` with dead links transformed (codebase/ → Pages URLs, docbase/docs/ → wiki page names, AGENTS.md → GitHub source URL)
- `TOCTREE.md` is generated from `docbase/TOCTREE.md` with links flattened for wiki root and the "Study content" section stripped
- `docbase/docs/*.md` are copied to the wiki root
- `_Sidebar.md` provides navigation (Home, TOCTREE, engineering docs)
- GitHub renders mermaid natively in wiki pages

## Data flow

```
dev-001 push
  → release (CHANGELOG bump)
  → fast_checks (validate-notes.sh)
  → security_checks (Sonar, optional)
  → promote (dev-001 → dev → main)
  → pages + wiki + sonar_baseline (parallel, from main)
```

All jobs chain in a single workflow run. `GITHUB_TOKEN` pushes do not re-trigger the workflow, keeping the pipeline atomic.
